# US-025: Appointment Conflict Detection

## Story

**As a** patient,
**I want** the system to warn me about double-bookings or scheduling conflicts,
**So that** I don't accidentally book overlapping appointments.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-002 |
| **Priority** | High |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] System detects overlap: patient has another appointment within 30 min before/after proposed slot
- [ ] Soft conflict (same day, different time): display warning but allow booking
- [ ] Hard conflict (overlapping time): block booking, display conflicting appointment details
- [ ] Staff override: staff can force-book despite hard conflict (with override reason)
- [ ] Provider conflict: system prevents booking if provider slot already taken (DB constraint)
- [ ] Conflict check occurs before slot lock (fail fast)
- [ ] SignalR notifies staff when conflict override is used
- [ ] Audit log for conflict detections and overrides

## Edge Cases

- Patient books with Provider A at 10:00, tries Provider B at 10:15 (30-min slots overlap) → hard conflict
- Cancelled appointment no longer triggers conflict detection
- Walk-in registration does not trigger patient conflict (staff discretion)
