# US-015: Session Management & Inactivity Timeout

## Story

**As a** security officer,
**I want** sessions to automatically terminate after 15 minutes of inactivity,
**So that** unattended sessions cannot be exploited, meeting HIPAA session control requirements.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-001 |
| **Priority** | Critical |
| **Story Points** | 2 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Each API request validates session exists in Redis (`session:{userId}`)
- [ ] Valid session TTL refreshed to 15 minutes on each request (sliding expiration)
- [ ] Expired session (Redis key absent) → API returns 401 "Session expired"
- [ ] Frontend detects 401 session expired → redirects to login with "Session expired" message
- [ ] Explicit logout deletes Redis session immediately
- [ ] Admin deactivating a user immediately deletes their Redis session
- [ ] Session includes: userId, role, loginTimestamp, lastActivityTimestamp
- [ ] No sensitive data (PHI) stored in session — only identifiers

## Edge Cases

- Concurrent tabs: all tabs share the same session; activity in one refreshes for all
- Network interruption lasting >15 min → session expired on reconnect
- Server restart → Redis retains sessions (serverless Upstash persists)
