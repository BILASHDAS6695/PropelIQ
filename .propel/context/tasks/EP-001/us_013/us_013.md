# US-013: Patient Self-Registration

## Story

**As a** patient,
**I want** to create my own account with email, name, phone, and password,
**So that** I can access the platform to book appointments and manage my health data.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-001 |
| **Priority** | Critical |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Registration form collects: email, first name, last name, phone number, password, confirm password
- [ ] Email validated for format and uniqueness (case-insensitive)
- [ ] Password enforces: minimum 12 characters, at least 1 uppercase, 1 lowercase, 1 digit, 1 special character
- [ ] Phone number validated for format (digits, optional country code)
- [ ] On success: User created with Role = "Patient", PatientProfile created, activation email sent
- [ ] On duplicate email: display "An account with this email already exists"
- [ ] Passwords stored using bcrypt hashing (via ASP.NET Identity)
- [ ] Registration action logged in audit trail
- [ ] API returns 201 Created with user ID (no password in response)

## Edge Cases

- SQL injection attempts in email/name fields → rejected by validation
- Concurrent registration with same email → database unique constraint prevents duplicate
- Extremely long input (>256 chars) → rejected by max-length validation
