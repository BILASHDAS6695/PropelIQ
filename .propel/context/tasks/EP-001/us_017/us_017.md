# US-017: Account Security — Lockout & Password Policy

## Story

**As a** security officer,
**I want** accounts locked after 5 failed login attempts and password changes enforced every 90 days,
**So that** brute-force attacks are mitigated and credential hygiene is maintained.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-001 |
| **Priority** | High |
| **Story Points** | 2 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Account locked after 5 consecutive failed login attempts
- [ ] Lockout duration: 15 minutes (configurable)
- [ ] Failed attempt counter resets on successful login
- [ ] Locked account login attempt returns 401 with lockout time remaining
- [ ] Password change enforced every 90 days (credential_expires_at tracked)
- [ ] Expired password → login succeeds but returns `passwordChangeRequired: true`
- [ ] Password history: last 5 passwords cannot be reused
- [ ] Admin can manually unlock a locked account
- [ ] All lockout and unlock events logged in audit trail

## Edge Cases

- User locked, then unlocks naturally after 15 min → next valid login succeeds
- Admin unlocks account during active attack → new failed attempts re-lock
- Password change with same password → rejected by history check
