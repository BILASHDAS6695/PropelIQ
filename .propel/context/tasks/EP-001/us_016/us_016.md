# US-016: Role-Based Authorization Policies

## Story

**As a** system administrator,
**I want** role-based access control enforced across all API endpoints,
**So that** patients, staff, and admins can only access features appropriate to their role.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-001 |
| **Priority** | Critical |
| **Story Points** | 2 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Three authorization policies defined: `PatientPolicy`, `StaffPolicy`, `AdminPolicy`
- [ ] Patient endpoints: booking (own), intake (own), document upload (own), profile (own)
- [ ] Staff endpoints: all patient endpoints + walk-in, queue management, arrival marking, conflict resolution, coding verification
- [ ] Admin endpoints: all staff endpoints + user management, audit log viewing, system reports
- [ ] Unauthorized access returns 403 Forbidden
- [ ] Resource-level authorization: patients can only access their own data (ownership check)
- [ ] Staff can access any patient's data within their authorized scope
- [ ] Authorization policies applied via `[Authorize(Policy = "...")]` attributes
- [ ] Policy configuration centralized in a single registration method

## Edge Cases

- Patient attempts to access another patient's data → 403
- Staff attempts admin-only endpoint → 403
- Deactivated user with valid JWT → session check blocks before authorization
