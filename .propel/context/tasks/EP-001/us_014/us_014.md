# US-014: Login & JWT Authentication

## Story

**As a** registered user (Patient, Staff, or Admin),
**I want** to log in with my email and password and receive a JWT access token,
**So that** I can securely access protected platform features according to my role.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-001 |
| **Priority** | Critical |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Login endpoint accepts email + password, returns: accessToken (JWT, 30-min), refreshToken (7-day), expiresIn
- [ ] JWT contains claims: userId, email, role, sessionId
- [ ] JWT signed with HMAC-SHA256 secret (configurable via environment variable)
- [ ] Refresh token endpoint accepts expired access token + valid refresh token, issues new pair
- [ ] Refresh tokens are single-use (rotated on each refresh)
- [ ] Invalid credentials return 401 with generic message (no email/password hint)
- [ ] Login creates a Redis session entry with 15-minute TTL
- [ ] Successful login logged in audit trail
- [ ] Failed login logged in audit trail (without password)

## Edge Cases

- Locked account attempts login → 401 with "Account temporarily locked" message
- Deactivated account attempts login → 401 with "Account is inactive"
- Expired refresh token → 401, must re-authenticate
