# US-034: In-App Real-Time Notifications

## Story

**As a** user (patient or staff),
**I want** to receive real-time in-app notifications for relevant events,
**So that** I'm immediately aware of changes without refreshing the page.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-004 |
| **Priority** | High |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] SignalR hub: `NotificationHub` with user-specific groups
- [ ] Notification types: swap_request, swap_result, appointment_reminder, arrival, status_change
- [ ] Frontend notification bell icon with unread count badge
- [ ] Click bell → dropdown list of recent notifications (last 20)
- [ ] Each notification: icon, message, timestamp, read/unread state, action link
- [ ] Mark as read on click or "Mark all read" button
- [ ] Notifications persisted in database for history (last 90 days)
- [ ] Toast popup for high-priority notifications (swap request, arrival)
- [ ] SignalR auto-reconnect with exponential backoff

## Edge Cases

- User offline when notification sent → delivered on reconnect (queued in DB)
- 100+ unread notifications → show "99+" badge, paginate list
- SignalR connection fails → fall back to polling every 30 seconds
