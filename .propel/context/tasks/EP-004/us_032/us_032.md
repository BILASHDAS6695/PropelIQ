# US-032: Email Notification Service

## Story

**As a** patient,
**I want** to receive email notifications for appointment events,
**So that** I stay informed about bookings, reminders, and changes without checking the app.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-004 |
| **Priority** | High |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Email service implemented using MailKit (SMTP)
- [ ] Email templates for: booking confirmation, cancellation, reminder, swap request, swap result, no-show follow-up
- [ ] Templates use HTML with inline CSS, responsive layout
- [ ] Template variables: patient name, provider name, date, time, appointment ID
- [ ] Emails queued via Hangfire (not sent synchronously in request)
- [ ] Failed email delivery retried 3 times with exponential backoff
- [ ] Permanently failed emails logged with error details
- [ ] SMTP credentials configured via environment variables
- [ ] Email service abstracted behind `INotificationService` interface

## Edge Cases

- Invalid email address → log warning, skip send, do not block workflow
- SMTP server unavailable → queue retries, alert admin after 3 failures
- Template rendering error → log error, send plaintext fallback
