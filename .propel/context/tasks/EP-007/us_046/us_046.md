# US-046: OCR Text Extraction Pipeline

## Story

**As a** system,
**I want** to automatically extract text from uploaded clinical documents using OCR,
**So that** the extracted text can be analyzed by NER and coding services.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-007 |
| **Priority** | Critical |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] OCR pipeline triggered automatically on document upload (via message queue or Hangfire)
- [ ] Tesseract OCR engine used for text extraction
- [ ] PDF: extract embedded text first; use OCR only for scanned/image PDFs
- [ ] Image documents (PNG/JPG/TIFF): OCR applied directly
- [ ] Extracted text stored in document record (JSONB field: `extracted_text`)
- [ ] OCR confidence score stored per page/region
- [ ] Document status updated: Uploaded → Processing (during OCR) → Processed (on completion)
- [ ] Failed OCR logged with error, document status → "ProcessingFailed"
- [ ] Processing time target: <30 seconds for a single-page document
- [ ] All OCR processing runs locally (no external API calls)

## Edge Cases

- Completely illegible scan → low confidence score, status "ProcessingFailed", flag for manual review
- Multi-page PDF (>20 pages) → process sequentially, update progress
- Corrupted file → immediate failure, status "ProcessingFailed", notify uploader
- Non-English text → best-effort extraction, flag language in metadata
