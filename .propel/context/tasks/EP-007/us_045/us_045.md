# US-045: Document Upload & Storage

## Story

**As a** patient,
**I want** to upload my clinical documents (lab results, referral letters, imaging reports),
**So that** my provider can review them before or during my appointment.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-007 |
| **Priority** | Critical |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Upload endpoint: `POST /patients/{id}/documents` accepts file + metadata
- [ ] Supported formats: PDF, PNG, JPG, JPEG, TIFF (validated server-side)
- [ ] Maximum file size: 10 MB per file
- [ ] File stored on local filesystem (configurable path via environment variable)
- [ ] Database record: documentId, patientId, filename, mimeType, uploadedAt, status, filePath
- [ ] Files encrypted at rest (AES-256)
- [ ] Upload linked to patient profile (accessible from 360-view)
- [ ] Document status lifecycle: Uploaded → Processing → Processed → Verified
- [ ] Virus scan on upload (ClamAV integration or file-type validation)
- [ ] Audit log entry for each upload (userId, documentId, timestamp)

## Edge Cases

- Unsupported file type → 400 "Unsupported format: .xyz. Accepted: PDF, PNG, JPG, TIFF"
- File exceeds 10 MB → 413 "File too large. Maximum size: 10 MB"
- Upload interrupted → partial file cleaned up, no DB record created
- Duplicate filename → append UUID suffix, store both
