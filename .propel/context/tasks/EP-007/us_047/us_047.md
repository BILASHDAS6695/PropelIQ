# US-047: Named Entity Recognition (NER) for Clinical Text

## Story

**As a** healthcare provider,
**I want** clinical entities (diagnoses, medications, procedures, lab values) automatically identified in documents,
**So that** I can quickly find relevant information without reading entire documents.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-007 |
| **Priority** | High |
| **Story Points** | 4 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] NER pipeline runs after successful OCR (chained processing)
- [ ] Uses spaCy/scispaCy with biomedical NER models
- [ ] Entity types extracted: DIAGNOSIS, MEDICATION, PROCEDURE, LAB_TEST, LAB_VALUE, ANATOMY, SYMPTOM
- [ ] Each entity stored with: text, type, start_offset, end_offset, confidence_score
- [ ] Entities stored as JSONB array in document record (`entities` field)
- [ ] Minimum confidence threshold: 0.7 (configurable)
- [ ] Entities below threshold stored but flagged as "low_confidence"
- [ ] Processing time: <10 seconds per page of extracted text
- [ ] NER results feed into medical coding (US-055) and 360-view (EP-008)

## Edge Cases

- No entities found → empty array, document still marked "Processed"
- Ambiguous entity (e.g., "Tylenol" as both brand and generic) → store both interpretations
- Very long document → process in chunks to manage memory
- Model unavailable → queue for retry, document status remains "Processing"
