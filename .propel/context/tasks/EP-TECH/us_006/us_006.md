# US-006: Shared Infrastructure — Logging, Health Checks, Error Handling

## Story

**As a** developer,
**I want** cross-cutting infrastructure (structured logging, health checks, global error handling) configured in the API,
**So that** all features inherit consistent observability and error response patterns from day one.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-TECH |
| **Priority** | High |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Serilog configured with JSON structured output and correlation IDs per request
- [ ] Log levels configurable via appsettings (Debug for dev, Information for prod)
- [ ] PHI-safe log redaction configured (mask email, phone, DOB in log output)
- [ ] Rolling file sink with daily rotation (dev); console sink (prod)
- [ ] Health check endpoint at `/health` validates: database connectivity, Redis connectivity
- [ ] Global exception handler middleware returns RFC 7807 ProblemDetails responses
- [ ] Unhandled exceptions logged at Error level with full stack trace
- [ ] Request/response logging middleware captures method, path, status, duration
- [ ] Correlation ID propagated via `X-Correlation-Id` header

## Technical Notes

- Use `Serilog.AspNetCore` for request logging enrichment
- Health checks use `AspNetCore.Diagnostics.HealthChecks` packages
- ProblemDetails returned for 4xx and 5xx responses with appropriate detail levels
- Never expose stack traces in Production error responses
