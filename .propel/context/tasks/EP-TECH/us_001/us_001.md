# US-001: .NET 8 Solution Scaffolding with Clean Architecture

## Story

**As a** developer,
**I want** a .NET 8 solution scaffolded with Clean Architecture layers (Api, Application, Domain, Infrastructure),
**So that** all subsequent feature development follows consistent patterns with proper separation of concerns.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-TECH |
| **Priority** | Critical |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Solution file `HealthPlatform.sln` created with four projects: Api, Application, Domain, Infrastructure
- [ ] Project references follow Clean Architecture dependency rules (inner layers don't reference outer)
- [ ] Domain project contains base entity classes (`BaseEntity`, `AuditableEntity`) with Id, CreatedAt, UpdatedAt
- [ ] Application project references MediatR with a sample command/query pipeline
- [ ] Infrastructure project references EF Core and Npgsql packages
- [ ] Api project configures dependency injection for all layers in `Program.cs`
- [ ] FluentValidation pipeline behavior registered in MediatR
- [ ] Solution builds successfully with `dotnet build`
- [ ] Unit test project created (`HealthPlatform.Tests`) with xUnit

## Technical Notes

- Target .NET 8 LTS
- Use nullable reference types (`<Nullable>enable</Nullable>`)
- Enable `ImplicitUsings` and `TreatWarningsAsErrors`
- Register MediatR behaviors: Validation, Logging
