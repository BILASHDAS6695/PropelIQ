# US-008: PostgreSQL Provisioning & EF Core Configuration

## Story

**As a** developer,
**I want** PostgreSQL provisioned with EF Core configured for code-first migrations and connection pooling,
**So that** the data layer is ready for schema creation and efficient database access.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-DATA |
| **Priority** | Critical |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] PostgreSQL 16 database provisioned (Neon or Supabase free tier for cloud; local Docker for dev)
- [ ] `ApplicationDbContext` created with entity sets for all core entities
- [ ] Connection string configured via environment variables (not hardcoded)
- [ ] Npgsql connection pooling configured (max 100 connections)
- [ ] EF Core conventions applied: UTC datetime conversion, snake_case naming
- [ ] Base entity configurations: `Id` (UUID), `CreatedAt`, `UpdatedAt` auto-populated
- [ ] `dotnet ef migrations add InitialCreate` executes successfully
- [ ] Database responds to connection test from the API health check

## Technical Notes

- Use `Npgsql.EntityFrameworkCore.PostgreSQL` package
- Configure `UseSnakeCaseNamingConvention()` for PostgreSQL conventions
- All DateTime properties use `DateTimeKind.Utc` conversion
- Connection string format: `Host=;Port=;Database=;Username=;Password=;`
