# US-009: Core Schema Migration — Entities & Relationships

## Story

**As a** developer,
**I want** the complete core database schema created via EF Core migrations covering all Phase 1 entities,
**So that** all features have their data tables available from the start.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-DATA |
| **Priority** | Critical |
| **Story Points** | 5 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Entity configurations created for all 15 core entities (DR-001 through DR-015)
- [ ] Primary keys use UUID (`Guid`) type
- [ ] Foreign key relationships configured with proper cascade rules
- [ ] Indexes created on: User.Email (unique), Appointment.PatientId, Appointment.ProviderId, AppointmentSlot.ProviderId+StartTime
- [ ] JSONB columns configured for: IntakeRecord.DataJson, ExtractedData.DataJson, PatientView360.ConsolidatedDataJson
- [ ] Enum columns stored as strings (not integers) for readability
- [ ] Soft-delete filter configured globally (`IsDeleted = false` query filter)
- [ ] Migration applies successfully to clean database
- [ ] Rollback migration (`dotnet ef migrations remove`) works cleanly

## Technical Notes

- Use `IEntityTypeConfiguration<T>` for each entity
- JSONB columns use `HasColumnType("jsonb")`
- Soft-delete implemented via `ISoftDeletable` interface and global query filter
- Concurrency tokens on frequently-updated entities (Appointment, PatientView360)
