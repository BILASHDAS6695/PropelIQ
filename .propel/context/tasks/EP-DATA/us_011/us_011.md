# US-011: Immutable Audit Log Infrastructure

## Story

**As a** compliance officer,
**I want** an append-only audit log with hash chain integrity that prevents any modification or deletion,
**So that** the system maintains HIPAA-compliant, tamper-evident records of all data access and changes.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-DATA |
| **Priority** | Critical |

| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] AuditLog table created with: Id, UserId, Action, EntityType, EntityId, Timestamp, Details (JSONB), PreviousHash, CurrentHash
- [ ] Database trigger prevents UPDATE operations on AuditLog table
- [ ] Database trigger prevents DELETE operations on AuditLog table
- [ ] Each new audit entry includes SHA-256 hash of previous entry (chain integrity)
- [ ] EF Core SaveChanges interceptor automatically captures entity changes
- [ ] Interceptor records: Created, Updated, Deleted actions with before/after values
- [ ] Audit logging does not block the main transaction (async write acceptable)
- [ ] Audit entries include the authenticated user's ID from the request context
- [ ] 7-year retention policy documented; no automatic purging configured

## Technical Notes

- Use `ISaveChangesInterceptor` for automatic audit capture
- Hash chain: `CurrentHash = SHA256(PreviousHash + Timestamp + Action + EntityId + UserId)`
- Store `Details` as JSONB with changed properties only (old/new values)
- PostgreSQL trigger: `CREATE RULE prevent_update AS ON UPDATE TO audit_log DO INSTEAD NOTHING;`
