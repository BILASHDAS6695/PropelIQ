# US-010: Upstash Redis Integration for Caching & Sessions

## Story

**As a** developer,
**I want** Upstash Redis connected for session management and data caching with proper TTL configuration,
**So that** the system supports fast session validation and reduces database load for frequently-read data.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-DATA |
| **Priority** | Critical |
| **Story Points** | 2 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] StackExchange.Redis client configured with Upstash Redis connection string
- [ ] TLS encryption enabled for Redis connections
- [ ] Session store interface: `SetSession`, `GetSession`, `DeleteSession`, `RefreshTTL`
- [ ] Session TTL set to 15 minutes (900 seconds) with sliding expiration
- [ ] Cache interface: `Get<T>`, `Set<T>`, `Delete`, `Exists` with configurable TTL
- [ ] Connection health check integrated into `/health` endpoint
- [ ] Graceful fallback if Redis is temporarily unavailable (log warning, bypass cache)
- [ ] Redis connection pool configured for concurrent access

## Technical Notes

- Use `StackExchange.Redis` package (not Microsoft.Extensions.Caching.StackExchangeRedis)
- Connection string via environment variable: `REDIS_CONNECTION_STRING`
- Serialize cache values as JSON (System.Text.Json)
- Key naming convention: `session:{userId}`, `cache:{entity}:{id}`
