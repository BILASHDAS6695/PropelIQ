# US-012: Seed Data & Repository Pattern Implementation

## Story

**As a** developer,
**I want** seed data for providers, insurance records, and appointment slots, plus a generic repository pattern,
**So that** features can be developed and tested against realistic data with consistent data access patterns.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-DATA |
| **Priority** | High |
| **Story Points** | 3 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Seed data creates 5 providers with different specialties
- [ ] Seed data creates 50+ dummy insurance records (name + member ID combinations)
- [ ] Seed data creates appointment slots for the next 30 days (9 AM–5 PM, 30-min slots per provider)
- [ ] Generic repository interface: `IRepository<T>` with GetById, GetAll, Add, Update, Delete, Query
- [ ] Unit of Work pattern: `IUnitOfWork` wraps DbContext SaveChanges with audit integration
- [ ] Repository implementations use EF Core DbSet operations
- [ ] Specification pattern for complex queries (e.g., available slots by provider and date range)
- [ ] Seed data runs automatically on first migration apply (via `HasData` or `DbContext.Seed()`)

## Technical Notes

- Use `IEntityTypeConfiguration.HasData()` for static seed data
- For dynamic seed data (dates), use a `IHostedService` that seeds on startup if empty
- Repository does NOT expose `IQueryable` outside Infrastructure layer
- Specifications implement `ISpecification<T>` with `Criteria` and `Includes`
