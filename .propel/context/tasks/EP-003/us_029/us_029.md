# US-029: Slot Swap Approval & Execution

## Story

**As a** patient who received a swap request,
**I want** to accept or decline the swap offer,
**So that** I can decide whether the proposed time works for me.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-003 |
| **Priority** | Medium |
| **Story Points** | 3 |
| **MoSCoW** | Should Have |

## Acceptance Criteria

- [ ] Target patient receives notification (email + in-app) about swap request
- [ ] Notification shows: proposed new time, current time, provider name (no requester identity)
- [ ] Target patient can Accept or Decline from notification or in-app
- [ ] Accept: both appointments swap slot references atomically (single transaction)
- [ ] Accept: both patients receive confirmation email with new time
- [ ] Decline: requester notified, swap request status → "Declined"
- [ ] Atomic swap: if either slot changes during execution → swap fails gracefully
- [ ] Both patients' calendar views update immediately after swap

## Edge Cases

- Target patient doesn't respond within 24h → auto-decline
- Concurrent swap requests for same slot → first accept wins, second auto-declined
- Database error during swap → transaction rollback, both appointments unchanged
