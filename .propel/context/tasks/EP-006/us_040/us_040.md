# US-040: AI Conversational Intake Engine

## Story

**As a** patient,
**I want** to provide my pre-visit medical information through a conversational AI chat,
**So that** I can complete intake naturally without filling out complex paper forms.

## Details

| Field | Value |
|-------|-------|
| **Epic** | EP-006 |
| **Priority** | High |
| **Story Points** | 5 |
| **MoSCoW** | Must Have |

## Acceptance Criteria

- [ ] Python FastAPI endpoint: `POST /intake/chat` accepts message + session context
- [ ] Local Ollama LLM used for NLP (no external AI APIs per ADR-004)
- [ ] Conversational flow gathers: chief complaint, symptom duration, severity, medications, allergies, medical history
- [ ] System asks follow-up questions based on responses (branching logic)
- [ ] Structured data extracted from natural language responses
- [ ] Session maintains context across multiple messages (conversation history in Redis)
- [ ] Conversation timeout: 30 minutes of inactivity → session closed, partial data saved
- [ ] API response time < 3 seconds per message (LLM inference)
- [ ] No PHI sent to external services (all processing local)

## Edge Cases

- Patient provides nonsensical response → "Could you please clarify?" follow-up
- Patient skips a question → mark as "not provided", continue flow
- LLM unavailable → fallback to structured form (US-041)
- Patient provides info in single message covering multiple questions → extract all, skip those questions
